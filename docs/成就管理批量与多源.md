# 成就管理、批量匹配与本机数据源

2026-10-23，当前 workspace 源码版，未打包或同步现有便携版／安装包。

## 入口与页面

- 左栏“资料补全”下新增 **成就管理**；资料补全窗口也可点击“批量补全成就”，沿用当前游戏范围。
- 独立页面包含 **游戏与成就 / 数据源 / 最近解锁**。总览显示当前记录的解锁数、总成就数及全部完成的游戏数；不做好友或联机账号统计。
- 游戏列表可按名称、本地／Steam、缺少定义、缺少记录及全部完成筛选；勾选条目后批量操作，没勾选则使用当前筛选结果。“补全缺失并检测记录”复用已有定义，“重新匹配所选”才强制更新定义。可停止，已完成内容保留。
- 单游戏页显示进度、成就名称／说明／图标，支持名称和说明搜索、已解锁／未解锁筛选、最近解锁及稀有度排序、主动显示隐藏成就。没有可靠时间的首次导入显示“时间未知”，不把导入时间伪装成历史解锁时间。
- 批量结果区分已就绪、已匹配但缺少记录、多账号待选择、尚未匹配和匹配失败；失败原因保留。游戏页展开“检测详情”可核对检查目录、文件解析失败原因和定义来源；“添加检测目录”只读检查自选目录。

## 开源适配与数据定位

按用户指定的 [justin-delano/PlayniteAchievements](https://github.com/justin-delano/PlayniteAchievements) 实现本地范围，参考版本为 `002eaa8b2cdcc5df4c6f4bf2d886c5fbbc2390b2`。

其 `SteamInstallLocator` 从注册表或配置定位 Steam，按账号和 App ID 组合 `appcache/stats/UserGameStats_<账号编号>_<AppID>.bin` 与 `UserGameStatsSchema_<AppID>.bin`。`SteamLocalStatsReader` 使用定义中的 cache-group / bit 对应关系解析进度位掩码及 AchievementTimes，并从计数型 stat 得到进度条。新的 `app/achievement_steam.py` 是这部分算法的 Python 适配，包含有界 KeyValues 解析、配对定义与计数条；保留 [MIT 许可](../ui/assets/third-party/PlayniteAchievements-LICENSE.txt) 及模块内署名。

上游是依赖 Playnite SDK 的 C# 插件，因此其 WPF 页面不能直接放进当前 Qt 程序。本轮按其总览、游戏成就、数据源和历史的结构接入 QML 页面；没有宣称已移植上游所有平台、OAuth、评分／奖杯自定义、录屏、好友及主题系统。

本地 JSON／INI 目录检测继续参考 Local provider 的做法，支持：

- 已有游戏资料、平台本身 ID、steam_appid.txt 和常见启动配置中的明确 App ID；Steam 平台自己的 ID 优先于封面资料附带的 ID。
- 游戏／EXE 目录、已配置存档目录、对应 App ID 的 GSE / Goldberg / CODEX / RUNE / OnlineFix 等位置，以及账号在前的常见目录布局；自选附加目录可补充非标准位置。
- 有界深度和条目数，跳过目录链接，不扫全硬盘。JSON／INI 支持更多常见文件名、INI 点号状态字段、UTF-8 / UTF-16 以及常见中文编码。
- Steam BIN 缓存按明确 App ID 只读查找，也支持在附加目录检测；不同账号的文件不会合并，多候选必须选择。

**找不到 INI 不等于检测坏了。** Steam 往往使用 BIN；而某些本地版本根本没有生成当前支持的成就记录。定义列表不会制造进度，本程序不替换 DLL、不注入游戏、不改原存档，也不会创建假的游戏成就文件。当前仍不支持任意自定义加密／压缩格式、所有平台的 SQLite／注册表进度或根据游戏画面推断解锁。

## 定义来源与缓存

- 自动：Steam 公开定义优先，失败时尝试已有本地定义／Steam 缓存，再尝试 SteamHunters；具体来源可在批量和单游戏页选择。
- Steam 与 SteamHunters 都按同一个明确 App ID 请求，以内部编号关联进度，不把不同平台或不同版本的成就列表按数量强行拼接。
- 本地没有 App ID 时，批量流程用现有 Steam 名称查找的高相似度及歧义阈值获取候选；不可靠的名称保留为待手动确认，不擅自套用第一条搜索结果。本地定义模式不发起名称联网查询。
- 定义、来源和记录索引保存在本机成就数据中，正常打开和启动复用缓存。图标队列遍历整套图标，取消了之前 30 秒后不再继续的截断；已缓存文件不重下，重新打开、批量补全或启动会续补缺失图标，软件退出时停止。下载失败显示缺失数量，下次补全重试。
- **SteamHunters 本机实查返回 HTTP 403**。已实现其公开 JSON 结构适配与自动回退，离线契约测试通过，但不宣称该源在此网络环境联网成功，也不绕过站点访问限制。Steam 公开接口及图标此前实查可用。

## Steam 与本地游玩

- 本地游戏启动前建立已有进度基线，真实游戏窗口确认后后台监听，新解锁通过独立弹窗显示，普通窗口与 Anime4K 流程共用；不抢焦点。
- **Steam 游戏只统计，禁用本程序解锁弹窗**，让 Steam 自身弹窗负责提示。Steam 通过已有客户端启动而暂未识别出子窗口时，也可继续安静同步本机缓存；获得实际窗口后跟随该游戏进程生命周期。
- Steam 缓存的写入时机由 Steam／游戏决定，不能把“每秒检查一次文件”说成 Steam 游戏保证一秒内落盘；不读取好友，不上传到 Steam 账号。
- 文件检查和持久化、网络、图标和批量编排分在独立后台队列；未变化的记录不重复读取。不会因一次成就进度更新重建整库或重置导航。
