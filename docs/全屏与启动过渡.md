# 全屏、选中边框与启动过渡

2026-10-16，源码迭代。未重建便携版、安装包或发布 GitHub；测试均使用隔离数据，未启动真实游戏。

## 操作

游戏库工具栏增加“全屏 / 退出全屏”，也可按 F11。支持手柄在筛选工具栏选中并按 A。保存本机全屏偏好，下次源码启动时恢复；从最大化进入全屏，退出后恢复最大化。此模式控制游戏库窗口，不修改游戏本身的分辨率或显示设置。

所有库布局的启动入口现在使用同一条过渡流程，包括原版、卡片启动按钮和手柄菜单：

1. 点击启动，显示封面和背景过渡；120 毫秒后提交一次启动请求，期间可取消。
2. 游戏在后台启动，同时播放完整 900 毫秒入场动画。先完成哪一项都不会提前结束过渡；关闭界面动效时使用静态等待页。
3. 确认属于本次游戏的窗口已可见、未最小化、未隐藏或挂起，并且大小与句柄保持至少 700 毫秒稳定，再交接到游戏窗口。
4. 交接前保持等待画面不透明，先切换游戏，再清理过渡层，避免淡出过程中露出游戏库。

等待过程中可按 B、Esc 或“返回游戏库”。提交启动请求之后返回只停止等待，不终止游戏进程。60 秒未找到窗口时可继续等待，或者返回；继续等待不会重复发出启动请求。实际启动失败保留错误和返回按钮，不自动循环启动。关闭/隐藏游戏库会清理等待及临时置顶；用户切去其他应用时释放置顶，不在就绪后强行抢回焦点。

## 检测边界与开销

窗口检测在独立工作线程运行，每 250 毫秒检查一次，仅在本次启动期间运行，使用较低线程优先级；既有自动备份监听不被占用。匹配启动 PID/后代、实际 EXE 路径或安装目录，排除库自身、Steam/Playnite 客户端、启动器、崩溃报告、更新器等窗口。启动期间暂停星图背景动效及影院预告。

这是 Windows 可见窗口检测，不向游戏注入代码，不捕获游戏画面，也无法确认 DirectX/Vulkan 第一帧或菜单是否已经加载。少数游戏先创建黑色主窗口、使用独占全屏、进程受保护或在其他显示器显示时，仍需实际体验；无法可靠识别时会保留等待/返回操作，不把“进程存在”直接算成就绪。Windows 前台窗口限制也可能阻止程序主动激活；不会模拟按键或绕过系统限制。

## 选中边框

书脊、抽出的书封、影院胶片和星图节点统一使用主题强调色，边框绘制在封面和扫光上方，并添加细暗边保证浅色封面上可辨认。影院不再保留被图片遮住的旧选中底框；星图固定金色选中框改为强调色，金色只保留在幸运反馈中。焦点离开游戏内容时清除强选中边框。原版卡片和磁贴原有整框保持。

## 验证

- 新增启动窗口状态检查：可见稳定才就绪、仅进程/无关窗口不就绪、窗口消失或改变尺寸重新计时、取消、路径边界和平台进程排除。
- 新增界面回归：真实隔离子窗口延迟显示后才交接、早就绪仍播完整入场、重复点击只启动一次、失败、超时继续等待、不理会取消后的旧回调、全屏 F11/恢复最大化/偏好保存、三种新布局的边框颜色和离焦清理。
- 相关启动、导入/启动参数和监听单元检查 25 项通过；界面回归包括新启动流程、新布局、手柄导航、封面动效、预告释放和资料补全。截图与运行记录保存在本机 `test-data/launch-review`。
