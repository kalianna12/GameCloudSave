## 卡顿原因与播放实现

之前的 QAudioSink 使用 Python QIODevice 补帧，音频供给受界面事件循环影响。即使移到 Qt 工作线程，部分 Python/Qt 调用持有全局锁时也会阻塞 Python 音频回调；仅增加缓冲会延迟下一声反馈。

现在在工作线程加载全部文件并初始化 Windows 自带的 XAudio2；交互时立即提交完整短音缓冲，由原生音频线程播放和混音。实时路径没有 Python 音频回调、readData 或补帧定时器，也不在按键时解码/读取文件。8 个并发音轨保留已有尾音，满载时跳过新声音；素材峰值上限约 0.28，主输出增益 0.44，为全部音轨同时播放预留空间。前台声音启用时维持原生静音循环；后台/关闭声音时停止，设备变化时重新初始化。

使用的 Windows 接口和缓冲生命周期依据 [XAudio2Create](https://learn.microsoft.com/en-us/windows/win32/api/xaudio2/nf-xaudio2-xaudio2create)、[XAUDIO2_BUFFER](https://learn.microsoft.com/en-us/windows/win32/api/xaudio2/ns-xaudio2-xaudio2_buffer) 和微软 xaudio2.h；结构按原头文件的 pack(1) 处理。只调整本应用主音轨，不更改系统或其他应用音量。当前实现面向本项目的 Windows 10/11 环境，不需要额外下载 XAudio2 或手柄驱动。

快速切换布局的界面测试另外发现书柜虚拟化条目的 reveal 方法可能已随重建移除，已在调用前检查方法可用性，避免延迟回调抛异常。
