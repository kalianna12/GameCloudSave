# 长按导航与异步卡片优化

2026-10-22。仅修改和测试 workspace 源码，不更新便携版、安装器或 GitHub 发行。

## 定位到的阻塞

1. 首页上下换行先 `forceLayout()`，再 `positionViewAtIndex()` 跳到目标以取得位置，最后跳回原位并启动动画。60次快速上下输入触发179次同步滚动写入，还同步生成被跳过栏目的卡片。
2. 侧栏切换会重新筛选 `backend.games` 这个 QObject 的 QVariantList 属性。剖析中的4次操作调用了游戏库 getter 约1940次，整库被反复跨语言取出；480款数据下出现约2.8–2.94秒的切换阻塞。这里不能通过再加几个工作线程解决，首先需要消除重复拷贝。
3. XInput 的原生查询和重复方向计算原本由GUI线程的16ms定时器驱动，界面忙时采样一起延后。
4. 重卡片同步创建、隐藏页面的卡片实例，以及反复跨 Qt 模型读取整条记录寻找ID，进一步放大冷加载与筛选成本。

## 最终修改

- `gamepad_sampling.py` 独立线程以约8ms间隔采样；失联时降低到350ms扫描。工作线程只处理原生输入、普通数据和有界邮箱，Qt界面访问及命令派发仍在GUI线程。最多32条待处理指令，一次待处理唤醒；长按重复按轴合并、反向及松开清除过期重复、右摇杆仅保留最新值。超过150ms的旧指令丢弃，避免恢复后补跳或误触发。前后台/设置切换使用采样代次隔离，恢复时预置已按住的A；关闭后停止线程。
- 映射运行器发出虚拟手柄索引变化通知，在GUI线程刷新采样排除配置；避免把虚拟输出再送回主界面。焦点变化本身不反复切换硬件连接状态，旧唤醒也不能误报断开。
- `LibraryMetrics.js` 统一栏目高度、卡片宽度和累计位置。首页按已知几何计算目标，直接重定向100ms滚动动画；不再为了测位置跳转、回退或强制布局。网格关闭自动高亮滚动与自定义滚动之间的竞争，书柜使用连续的目标滚动。
- 首页的逻辑选择与当前已实例化的ListView行分开。快速跨过未加载的行时，列位置、分页和选中游戏ID仍可计算；行出现后再应用选择。更新/重排保留游戏ID，并验证当前实例对应正确栏目，防止引用池中旧行。
- 主页、网格、书柜卡片使用异步Loader；当前选中项优先完成，其他卡片分批创建。加载时保留基础表面，隐藏页停用卡片及滚动，隐藏首页推迟模型更新。沿用已有2ms的引擎孵化时间片及Qt异步图片加载，不从工作线程创建QML对象。
- 增加 `libraryRevision`、`libraryGames()`、`libraryGroups()` 和按ID索引的 `libraryGame()`。主页面在库变化时取得副本，筛选/排序复用快照；游戏设置、封面选择和手动资料页按ID取单个记录。该处理方式符合 [Qt关于属性引用序列与函数返回副本的性能说明](https://doc.qt.io/qt-6.8/qtquick-performance.html#sequence-tips)。
- 网格同步在同一事件循环合并，使用本地ID顺序查位置，避免循环从Qt模型复制记录；仅更新变化记录，批量删除尾项。侧栏进入新范围明确重置首项，普通数据更新仍保持当前ID与模型身份。
- 搜索120ms防抖使用GUI事件循环的Qt精确定时器，避免依赖QML动画时钟；返回/切换时仍可取消。非标准嵌入宿主也为异步卡片安装孵化控制器。
- 切换手柄/鼠标时，卡片使用窗口实际鼠标移动序号判断新移动；恢复HoverHandler或复用卡片本身不会误触发旧鼠标倾斜，真正的第一次鼠标移动仍即时生效。输入模式切换后延迟到通知完成再恢复当前控制器提示动画，避免被重置信号顺序截断。

## 测量

480款隔离游戏、24栏、12张800×1120的PNG，1920×1080逻辑窗口，D3D11。快速输入间隔20ms，明显快于实际长按约85ms的重复节奏。结果是本机观测值，不是所有设备的保证。

| 指标 | 定位阶段 | 修改后代表记录 |
| --- | ---: | ---: |
| 首页60次上下，处理时间中位数 | 35.93ms | 2.08ms |
| 首页处理时间P95 | 198.08ms | 10.31ms |
| 导航过程中同步滚动写入 | 179 | 0 |
| 网格48次上下，处理时间P95 | 未单独采集 | 14.35ms |
| 侧栏切换处理时间P95 | 约2938ms | 16.57ms |
| 侧栏操作中的整库getter读取 | 4次操作约1940次 | 16次操作0次 |
| 实际采样器模拟1秒长按 | — | 9个方向指令，松开后稳定 |

源码运行报告在忽略目录 `build/vertical-navigation/`，包含before/after JSON及可选的cProfile数据。`--profile`只用于找热点，带剖析开销的数据不作为时间阈值验收。

帧监测最终使用排队的GUI通知，避免Python直接进入渲染线程抢GIL。早期before探针用了直接连接，因此帧间隔不做严格倍率对比；这些通知间隔也不是显卡呈现时间。本轮高DPI连续冷加载压力测试仍见长间隔，不能宣称零掉帧或已经验证显示器扫描层面的撕裂完全消失。已验证的是输入阻塞、重复整库传递及同步跳回问题。

## 验证

- `test_gamepad_sampling.py`：9项，通过独立线程查询、30ms短按、400ms GUI暂停、重复合并、松开、32项上限、陈旧指令、代次隔离、真实GUI线程派发、虚拟索引变化与按住A恢复保护。
- `test_vertical_navigation_performance.py`：实际QML带图压力；主页/网格/侧栏处理时间与无同步跳转断言；没有事件循环机会的18次下+3次右仍选择正确游戏363；生产采样器与派发路径的真实长按/松开测试。
- `test_navigation_grid_retry.py`、`test_navigation_v232.py`、`test_home_spatial_input.py`：列数与相邻位置、工具栏/侧栏/弹窗保护、A/Menu/Y、四布局及摇杆倾斜。旧v232夹具关闭后来加入的推荐栏目，确保测试第二栏仍是类别；同步注入测试显式选单线程适配器，生产线程路径由新增测试独立覆盖。
- `test_home_ui_v23.py`、`test_shelf_incremental_ui.py`、`test_new_games_save_scope_ui.py`：筛选与搜索、滚动保留、更新0/1条记录、无模型重置、新加入与存档跟进。
- `test_experience_navigation.py`、`test_immersive_controls.py`、`test_immersive_preferences.py`、`test_designs_and_personalization.py`：书柜/影院/星图、全屏返回、分组、外观与提示。
- `test_ui_enrichment.py`：资料、封面和手动补全的实时更新与取消。
- `test_input_mapping.py`：37项；`test_mapping_capture_ui.py`：录入隔离与大模型，两者通过，没有真实输入注入。
- `test_cover_motion.py`：一次性提示动画、鼠标即时倾斜、静止不持续渲染、输入方式切换、减少动效和滚动保护。

所有写入测试使用临时Store或专用隔离输出目录。真实 `data` 的287个文件仍与此前SHA256基线一致。正在运行的 `source-preview` 相对早期基线已有游戏库、配置及自动备份变化，本轮未对该目录发起游戏/备份操作，也未回滚这些差异。重启源码版使用本轮修改。
