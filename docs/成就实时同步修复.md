# 成就实时同步修复

2026-10-24，仅修改与测试 workspace 源码，未打包或同步便携版。

## 原因与修改

- 原监听只在游戏库启动游戏、且识别到游戏窗口后读文件。现在已配置记录在后台约每秒检查，等待独立启动器时也可同步；直接启动游戏可以同步统计，但游戏内弹窗仍需要游戏库确认对应窗口。
- 原文件变化只在当次刷新详情，页面忙碌时会丢弃刷新。现在合并实时进度、保留搜索中的状态和候选版本，封面计数与统计总览同步更新。
- 原签名只有记录文件属性；SSE 等记录在定义到达前无法对应内部编号，之后同一文件会被跳过。现在签名包含定义编号，同时保留首次原始基线，避免补齐定义时重播旧解锁。
- 文件断写、原子替换、暂时消失、读取失败保留历史并自动重试。即使一次后台检查发生异常，也会释放检查中的标记。
- 成就页增加监听状态，区分后台同步、尚无记录、多个账号、读取失败与关闭监听。

已知文件每秒仅检查属性，变化后才解析；仅当前选中或启动中的未匹配游戏每隔约 8 秒进行有范围限制的发现，不扫描全库目录。网络和图标任务继续独立于记录线程。

## 验证

`tests/test_achievement_realtime.py` 使用隔离目录与真实一秒计时器：未调用手动 poll 的外部写入约 985ms 更新页面和封面计数；等待窗口、搜索忙碌期间仍同步；断写重试与原子替换恢复；旧记录不重播；定义延迟情况下首次基线不误弹、期间新增解锁仍可通知；关闭监听生效。未变化文件不重新解析、不重新扫描。

29 项解析／来源单元测试、原异步边界测试、实际 QML 成就管理／四布局徽标／Steam 静默计数回归通过。测试使用临时游戏记录，不能视为真实游戏已能产生记录的证明。

只读复查：卡赞的 RUNE 成就文件不存在；寂静岭 f 与最后生还者 2 的 RUNE 成就文件均为 0 条。尚无可读新记录的游戏，无法仅凭下载成就列表更新进度；仍需核对实际运行版本的记录输出。未启动游戏或修改游戏目录、DLL、真实游戏库、配置、存档。

运行中的程序不会自动重载源码，体验修复需要重新启动源码版。

## Ori／Steam 补充验证

用户明确反馈：Steam 内 Ori 已解锁，但游戏库必须进入成就页才同步。只读检查《奥日与萤火意志》当前 Steam BIN 与游戏库进度缓存均为 9 项，解析器能识别已有记录；该快照是在用户进入页面后取得，不能据此否认此前的刷新问题。

针对性 QML 回归增加：成就页始终关闭，无 begin/attach 会话、不调用手动 poll，Steam 测试缓存新增解锁后，实际封面徽标约 812ms 从 1 自动变成 2，统计同步，主库模型版本不变，没有本程序重复弹窗。随后启动会话再次更新到 3 也正常。

Steam 进度解析还依赖配套 `UserGameStatsSchema_<AppID>.bin` 的分组与位定义。监听签名现包含这份文件的属性，并在读取前后检查两文件稳定性，防止只更新定义时仍跳过重读。新增回归验证进度文件完全未变、仅配套定义变化，也能更新统计。30 项单元与 QML 回归通过；测试记录仍为隔离数据，未解锁或改动真实 Ori。
