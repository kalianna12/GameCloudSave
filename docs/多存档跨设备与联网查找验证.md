# 多存档、跨设备与联网查找

2026-10-17，本轮只更新并测试 `workspace` 源码。便携版、安装包和 GitHub 发行包保持 V2.5.0，未同步本轮修改。重启本目录的 `启动源码版.bat` 使用新流程。

## 查找存档

原来的联网步骤主要查 Steam 游戏名称、开发商等资料，DeepSeek 识别名称时也没有直接执行网页检索。因此，游戏内部工程名与游戏名无关时，仅靠名称匹配容易漏掉目录。

现在增加真实 DeepSeek Search API：本地、规则和原有资料识别仍先执行；没有可靠结果才做网页初查，仍未找到再做一次深查。可靠的本地结果会跳过这部分请求。网页查询需要已有 DeepSeek Key，可能产生服务费用；失败、超时和权限错误显示提示，并保留已找到的本地结果。

在“查找存档”的匹配设置中，开启联网、DeepSeek 和“未找到时网页深查”。扫描进度区分“网页初查”和“网页二次深查”。结果附来源链接；网页内容只作为路径证据，不作为执行指令。模型给出的路径必须能在它引用的检索原文中核对，再验证本机目录；同时直接提取原文中的路径，避免模型漏掉备用目录。来源缓存有效期为 24 小时，取消后不再应用旧任务结果。

卡赞规则同时包含：

- `%LOCALAPPDATA%\The First Berserker Khazan\Saved\SaveGames`
- `%LOCALAPPDATA%\BBQ\Saved\SaveGames`

两处路径可能与启动方式有关，不能假定所有电脑都只使用 `BBQ`。有实际进度的两个候选同时存在时，保留歧义供用户确认。路径差异可参考 [Steam 用户的实际记录](https://steamcommunity.com/app/2680010/discussions/0/595144651000835275/)。接口依据为 [DeepSeek Search 使用说明](https://api-docs.deepseek.com/zh-cn/guides/search/) 和 [Search API](https://api-docs.deepseek.com/zh-cn/api/search/)。

其他匹配调整：

- Steam 自有游戏按 AppID 查找 `userdata` 对应账号目录，不要求目录名包含游戏名。
- 过滤只有设置、缓存或空文件的自动确认候选；保留手动选择入口。
- 扩大文件抽样，避免前面大量配置文件遮住后面的存档文件。
- 区分续作编号，兼容罗马数字与阿拉伯数字，减少原作目录被续作误选。
- 自动流程拒绝多个游戏指向相同或互相包含的目录。

## 筛选与确认

查找结果和批量确认共用状态筛选，可查看全部、未配置、未找到候选、待确认、已配置以及失败项。关键词可匹配名称、英文名、别名和已应用目录。查询仍在后台执行，结果陆续显示。

批量操作只处理当前可见结果中的勾选项；被筛选隐藏的旧勾选不会一起执行。

## 多存档恢复

备份保留根目录中的所有存档槽、游戏自带备份、空槽目录与公共设置。旧配置只选中某个槽时，符合规则的目录会提升到游戏存档容器，避免漏备份同级槽。

在存档历史中点“恢复”先打开预览：读取文件数、目标目录、可识别的存档槽和账号目录，确认后才恢复。云端备份先下载并检查，预览不会覆盖当前存档。

可以恢复全部，或选择一个槽。单槽恢复保留其他槽和当前公共设置；`SaveGameNN` 形式的配套文件会一起恢复，避免只还原 Player 而漏掉 Slot、备份等文件。

恢复会校验归档哈希、ZIP 内容和路径；先在同一磁盘准备完整待恢复目录，再保存恢复前副本并切换目录。切换失败时回滚原目录，恢复前副本继续保留。目录中的符号链接、连接点以及共享系统根目录会被拒绝。

## 跨设备

新备份记录游戏平台和自有平台 ID。Steam、Epic、Ubisoft 的同一游戏可以跨不同本地条目 ID 和不同显示名查找历史；仅用于资料匹配的 Steam 链接不会当作所有权 ID。

上传后会维护云端 `.gamecloud-index` 下的游戏目录索引。每个目录独立保存指针，避免两台设备同时更新时覆盖另一台的索引。已知的平台 ID 不一致时，不会因为名字相同就接收该备份。

备份账号目录与本机已有账号不同时，预览要求明确选择“备份账号 → 本机账号”。选择后只恢复该账号，可继续选单个槽，并保留其他账号。云端备注更新仍保留原备份的来源设备。

## 已知范围

- 每款游戏仍配置一个存档根目录；支持其中的多个槽和账号，尚未支持任意分散路径的合并备份。
- 槽位识别覆盖常见命名目录及 `SaveGameNN` 配套文件；其他结构可恢复整个目录，不会猜测未知文件之间的依赖。
- 账号映射只改变目录归属，不改写存档内部账号绑定、加密或校验。不同游戏版本、平台或账号是否能读取，仍由游戏决定。
- 跨设备建议两端使用本轮源码。旧版不会生成新索引；旧云端目录若完全改名、又没有平台索引或原始名称线索，不能自动发现，需要原设备上传新备份或手动整理旧记录。
- 历史列表显示最近 200 份，较早备份仍保留在云端，可从云端文件浏览器查看；不会为满足列表上限删除云端文件。
- 本轮没有执行真实游戏内的加载测试，已验证的是归档内容、传输、目录映射与恢复结果。
