# 游戏设置与资料补全：评估与实现

2026-10-10。本轮仅修改 workspace 源码并用隔离数据测试，没有构建或同步便携版、安装包。

## 实施前评估

按任务入口、名称一致性、信息层级、操作反馈、容错和窗口缩放检查当前界面。结论：视觉风格已有一致基础，但设置与资料完善流程尚不适合直接交给新手。

| 检查点 | 原界面表现 | 本轮调整 |
| --- | --- | --- |
| 任务入口 | 本机设置、单游戏资料、封面搜索分散在多个弹窗 | 卡片齿轮统一打开“游戏设置”，固定三个页面 |
| 信息层级 | 存档、启动参数、封面混在一个长表单 | 存档与云端、游戏封面、游戏资料分别成页；启动参数可展开 |
| 操作名称 | “本机设置”“编辑资料”“搜索封面”互相跳转 | 页面名称对应玩家的任务，按钮明确写保存、查询、应用 |
| 容错 | 日期补全直接写入，缺少整体预览 | 查询只生成候选，预览后应用；应用时再次检查缺失项 |
| 导入引导 | 导入后自动查询，不能选择仅导入 | 明确选择导入并查询或仅导入 |
| 过程反馈 | 通用“正在处理”不足以说明进展 | 分阶段进度、逐条预览、停止查询、单条失败可重试 |
| 小窗口 | 日期常在表单底部，部分入口不易发现 | 日期前置，表单滚动；资料补全放在侧栏库导航之后 |

这是基于实际界面和操作流程的评估，不代替真实新手体验测试。调整后的名称、步骤和按钮已通过实际 QML 界面验证，仍等待用户体验。

## 视觉与布局计划

保留用户的深色主题与绿色强调色。沿用 Theme 的背景 #181a1c、侧栏 #202326、表面 #282c30、边界 #454d56、文字 #f3f5f7 和强调色 #80c942；其他主题继续使用相同的 Theme 接口。

字体保持 Microsoft YaHei UI；页面标题 28px，区域标题 18px，正文 13px，来源信息 11–12px。表单和说明左对齐，窗口边距 24px，控件间距 12–14px。强调色用于主要动作与选中状态；不新增装饰性动画或背景。

库内任务采用以下结构：

```text
游戏卡片齿轮 → 游戏设置
  ├─ 存档与云端：本机存档目录、备份记录、共用 DAV 连接、启动参数
  ├─ 游戏封面：当前封面、查询、候选图片、本地图片或图片链接
  └─ 游戏资料：日期、主分类、标签、系列、单游戏查询与手动保存

侧栏“资料补全” → 选择查询内容 → 后台查询 → 预览 → 应用所选补全
导入所选 → 仅导入 / 导入并查询 → 新导入游戏的补全预览
```

审视计划后保留现有视觉系统，将改动集中在入口、分组和过程反馈，避免让游戏库看起来像另一套程序。批量列表用游戏名称、现有资料、新增内容和封面预览形成对应关系。

## 单游戏设置

- 原卡片齿轮仍是入口，固定三个页签：存档与云端、游戏封面、游戏资料。
- DAV 是所有游戏共用的连接。第一页显示连接及备份文件夹，提供直接进入连接设置的按钮；初次进入连接设置不会自动发起失败的网络请求。
- 封面查询内嵌在第二页；点击“使用此封面”、本地图片或链接是明确的手动更换操作。游戏 A 的结果不会被游戏 B 或导入候选复用。
- 第三页支持手动编辑，查询按钮打开只针对当前游戏的补全预览。未保存的表单草稿保留，应用补全时仅刷新未编辑的字段。
- 保存存档和保存资料互相独立。后台查询时可切换页签和关闭窗口。

## 批量补全

侧栏“资料补全”可查询全部游戏；单游戏入口和导入入口可限定范围。

- 资料包括完整发行日期、主分类、标签、系列和缺失封面。用户可选择本次查询的内容。
- Playnite、Steam、VNDB 提供资料与图片；DeepSeek 辅助名称匹配以及缺失分类、标签和系列。已有 Key 时默认选中，可取消；可在窗口直接设置并测试 Key。日期不会由 AI 推测。
- 先在快照中查询和生成候选，原游戏库不变。封面下载到缓存供预览，不更改当前游戏封面。
- 默认显示有可补全结果的条目。勾选“显示全部查询结果”可查看已有完整条目或未匹配原因。
- 预览显示来源、新增字段、候选封面和匹配名称。不能可靠匹配的内容保持空白，可到单游戏设置继续处理。
- 点击“应用所选补全”后再次检查实时数据。已有有效封面、日期、非默认分类、标签和系列保留；人工保存的空字段保护标志也保留。预览后人工新增的数据优先。
- 手动更换封面、手动修改资料属于用户明确编辑，与批量“只补全”分开。

## 导入选择

点击“导入所选”后提示是否查询缺失资料、标签和封面：

- 仅导入：保存来源已有的资料，不额外查询网络或调用 DeepSeek。
- 导入并查询：导入成功后打开仅包含新条目的补全预览，不自动应用。可取消 DeepSeek 辅助。
- 重复项确认仍保留，未导入新条目时不会误触发全库补全。

## 响应与停止

查询在工作线程中进行，每次最多两个游戏并发；逐条结果通过 Qt 信号更新稳定列表，避免重新生成整个列表导致位置跳动。元数据和搜索结果可缓存复用。

停止后不再开始后续网络请求；当前请求返回后收尾，已有候选仍可预览和选择应用。查询失败不会改变游戏库，也不会让错误条目中止其他游戏的结果。

尚未适配手柄的编辑页继续使用鼠标；手柄方向与确认命令不会在这些页面乱跳，B 可返回。
