# 游戏画质增强（源码版）

2026-10-22。范围按用户选择：实时超分、锐化、全屏放大，每款游戏单独保存方案。

## 使用

1. 游戏设置 → **画质增强**。首次使用点击“下载并安装内核”，或者从官方下载页取得 **Magpie v0.13.0 对应架构 ZIP 原包**，选择“导入官方 ZIP”。
2. 打开启用开关，选择算法、锐化和显示方式，点击“保存画质方案”。
3. 游戏先设为窗口模式，保留原始/合适的渲染分辨率。从游戏库启动时自动应用；也可以保存后点“应用到已运行游戏”，再切回游戏。
4. **Ctrl+Alt+F11** 切换缩放。设置页可停止增强。游戏进程退出后停止内核，退出软件也清理本软件启动的内核。

Anime4K 轻量/精细用于动漫、Galgame，分别使用内核原有 `Anime4K_Upscale_Denoise_S/L` 着色器，再以 Lanczos 适配输出。FSR 使用 EASU/RCAS；Lanczos 可以叠加 CAS 锐化；像素方案使用最近邻。锐化 0 会移除额外锐化通道，像素方案始终不加锐化。

全屏保持比例默认开启，也可拉伸；窗口模式支持 1.25–4 倍。输出帧率上限 30–240，控制内核 GPU 开销，**不是补帧**。FPS/TPS 可打开 3D 鼠标模式，VN/菜单光标操作保持关闭；3D 鼠标模式与窗口放大互斥。Windows Graphics Capture 为默认，提供 DWM 兼容捕获选项。

窗口需可被系统捕获；独占全屏须先改为窗口。受保护的画面或某些游戏可能不能捕获，应尝试兼容捕获并查看内核日志。首次编译效果可能需要等待。尚未完成不同游戏、显卡、HDR、反作弊环境的兼容性验证。

## 内核与文件

使用独立进程的 [Magpie v0.13.0 官方发行](https://github.com/Blinue/Magpie/releases/tag/v0.13.0)，上游 [GPL-3.0 许可及对应源码](https://github.com/Blinue/Magpie/tree/v0.13.0)。运行要求见 [官方 README](https://github.com/Blinue/Magpie/blob/v0.13.0/README_ZH.md)：Windows 10 1903+、DirectX 功能级别 11。不同着色器的作者/许可保留在官方原文件中。

不把内核二进制提交进仓库或同步到便携版；只有用户点击安装后才下载。下载及本地导入都验证官方发行资产 SHA-256，固定版本避免配置协议漂移：

| 架构 | SHA-256 |
| --- | --- |
| x64 | `a3f774dce9d2e050fb0934c362d51d8db459a2e79e6f937bdb86852312899a9e` |
| ARM64 | `3f1d4f8fade6da13402ac4ea739867d60f0dee50e4c4fa56aab508eab0109551` |

方案存储在本机 `machines/<identity>/games.json` 的游戏 `graphics` 字段，保留 EXE、存档目录等已有字段。内核在所选数据根目录 `engines/magpie-0.13.0-<arch>/`，使用自身 `config/config.json` 便携配置，不改 `%LOCALAPPDATA%/Magpie` 或用户已有 Magpie 的配置。下载/解压临时目录在同一 engines 目录；安装暂存、校验后再替换，失败回滚，阻止路径穿越和链接条目，限制下载/解压大小。保留来源通知和对应源码链接。

Magpie 为全局单实例：若用户已启动另一个 Magpie，明确提示先退出，**不会退出其他实例**。非游戏窗口的默认缩放方案禁用，快捷键不会把专用算法应用到其他窗口。所有停止操作只针对本软件持有的 Popen 进程和线程消息，不广播全局退出。首次启动不自动下载或申请管理员权限。

## 启动、异步与状态

`app/graphics_enhancement.py` 负责方案校验、安装和进程控制。耗时工作使用专用串行线程池；方案持久化复用 Bridge 已有串行任务队列，避免与导入/游戏设置同时写本机配置。下载和窗口等待支持取消，回调代际保护，退出时取消并排队清理。

`finishLaunchPresentation` 在稳定窗口交接之后调用自动启用，使用**实际窗口的 EXE、窗口类名**生成精确规则，处理 Chromium/WPF 等类名标准化；放弃交接时不启动。手动应用复用启动探针识别游戏；不能识别时提示补齐实际游戏 EXE。

捕获、GPU 计算着色器和显示由独立 Magpie 进程完成。Qt 不逐帧截图、不读回图像、不跑 CPU 图片滤镜。只有启动内核后每秒后台检查一次：未发现实际缩放窗口显示“就绪”；原生缩放窗口出现才显示“运行中”。目标 PID 与进程创建时间同时校验，避免 PID 复用误认。设置保存和轮询分离，轮询不阻止用户保存，也不每秒闪烁加载指示。

## 本轮验证与边界

- `tests/test_graphics_enhancement.py`：10 项通过，包含数值校验、真实着色器链、窗口规则、隔离保存两款游戏并重读、篡改 ZIP 拒绝、官方 ZIP 实际安装与缺件修复、取消、启动交接、其他 Magpie 不受控制、PID 复用清理、安装中游戏交接排队。
- `tests/test_graphics_ui.py`：实际 Main/QML 四页设置、保存/重开、深色/浅色/小窗口，无 QML 错误；截图 `build/graphics-review/`。安装入口位于上方，避免埋在长页面底部。
- 原有 `test_launch_ready.py`、`test_launch_ui.py`、`test_ui_enrichment.py`、`test_cover_motion.py` 通过，四页结构断言已相应更新。
- 原有手柄采样 9 项回归中，GUI 暂停/长按一项首次时序断言失败（收到 2 次而阈值 1 次），单项复跑通过；本轮没有修改采样实现，不将此次复跑当作消除该时序边界的证据。
- `tests/test_graphics_native.py --run` 使用官方内核及独立动画测试窗口，无真实游戏启动/存档操作。**本轮实际内核启动、读取专用配置、退出均已观察到；GPU 缩放输出尚未验证通过**：当前《奥日》在前台，Win32 不允许测试窗口取得前台，内核停在 ready，未出现缩放窗口。没有把“进程已启动”算作画质生效，待用户切回桌面后再运行六组算法/显示方式及目标退出实测。
- 原有 `data` 287 文件对既有基线 SHA-256 一致；运行中的 `test-data/source-preview` 是实际用户库，不作为测试夹具、不回滚其自身变化，本轮未在其中安装内核。所有写入测试均使用临时隔离 Store 或忽略的 build。
