# 成就弹窗性能与开关、退出修复

2026-10-25，源码版。用户确认掉帧发生在成就弹出的瞬间。

## 弹出路径

原实现首次解锁时才创建原生窗口，同时在 GUI 线程加载完整图标；显示期间每 150ms 再次调用 Windows 置顶。现在在本地游戏启动前创建隐藏窗口、初始化字体和捕获排除属性；图标由现有成就工作线程解码至最大 120px，并采用按修改时间失效的 64 项缓存。显示时只把准备好的小图像转为 QPixmap，置顶仅在显示／恢复时执行。

`test_achievement_overlay_latency.py --compare` 读取源码回溯点 `96861f7` 对比。在 2048×1024 测试图标和首次窗口创建的压力场景中，最近一次首弹 GUI 路径为 28.079ms → 1.382ms，窗口创建次数 1 → 0，连续 30 次可见状态检查期间的置顶调用 32 → 1。慢解码期间 Qt 心跳继续运行。数据是测试进程的调用耗时，不是真实游戏 FPS 或完整桌面显示延迟。

图标后台读取依据 [Qt QImageReader 文档](https://doc.qt.io/qt-6/qimagereader.html)。独立桌面弹窗仍可能影响游戏的显示合成路径；[微软 Flip Model 文档](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/for-best-performance--use-dxgi-flip-model) 说明其他内容覆盖游戏时的合成切换行为。因此没有宣称消除所有显卡／显示模式下的掉帧。

## 总开关与单游戏开关

成就管理顶部增加「成就系统」总开关，状态单独保存。关闭立即停止监听定时器，清掉当前／排队弹窗，取消自动批量检测，并拒收关闭前仍在途的监听结果。历史成就和统计保留，可手动查看。

重新开启后恢复原有游戏会话，先静默导入关闭期间已有的解锁，再提示之后的新解锁。开关操作按顺序异步保存，快速来回切换也保留最终值。成就总开关与音量等设置共享文件的写入增加互斥，避免同时修改造成覆盖或临时文件冲突。

单游戏「监听」「游戏内弹窗」现在切换立即生效，无需再点击保存，也不受页面正在匹配／读取的忙碌状态阻挡。这些开关单独写入，不会顺带保存尚未确认的记录路径或定义来源。通知在投递前再次校验当前开关及版本，拒绝开关变更前的迟到结果。Steam 条目仍统计成就，使用 Steam 自带弹窗。

## 退出清理

检测到游戏进程结束时，保留最后一次进度同步，清空该游戏的当前／排队通知，不再投递退出时产生的弹窗。程序真正退出时，优先关闭成就系统；即使后续其他模块清理失败，也不会留下成就弹窗。关闭后的定时器回调和迟到后台结果均受防护，已排队的开关写入允许保存完成。

原有「关闭主窗口时留在托盘」设置保持原语义：留在托盘时仍可按总开关继续监听游戏；托盘菜单的「退出」会完整关闭。这里没有把关闭游戏、隐藏库窗口和退出程序混成同一操作。

## 验证与范围

- `tests/test_achievement_controls.py`：实际 QML 鼠标操作，900／1280px 总开关布局，立即关闭、快速切换保存、页面忙碌、迟到监听结果、关闭后再开启的真实记录同步、设置并发写入、游戏退出、其他模块清理异常和退出后迟到投递。
- `tests/test_achievement_exit.py`：启动真实源码入口，显示一个成就弹窗且再排队一个，然后退出进程，验证窗口和队列均清除。
- `tests/test_achievement_overlay_latency.py --compare`：首弹开销、后台图像解码、有限缓存、前后台切换显示、移除通知和关闭回调。
- 原实时同步、异步匹配、实际游戏库 Steam 定时更新徽标和四布局成就页面回归；33 项成就及音效设置单元测试。

普通预览和真实程序退出已验证。`test_achievements_ui.py --gpu` 的临时游戏窗口未能获得并保持前台，测试停在前台校验／弹窗等待阶段，未完成本轮实际 Anime4K 覆盖测试；没有放宽生产前台保护规则。实际游戏首弹帧时间仍需用户重启源码版后复测。

测试使用临时数据，真实 `data` 目录的 287 个文件 SHA-256 保持不变。没有启动真实游戏、修改真实游戏成就或存档，也没有打包或更新便携版。性能报告及截图位于 `build/achievement-overlay-review`。
