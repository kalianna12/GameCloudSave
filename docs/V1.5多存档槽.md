# V1.5 多存档槽

同一游戏的 `save1`、`save3`、`ChallengeSave` 等目录不再被当成只能选一个的候选。匹配、手动选择和旧配置备份时，会识别同一父目录下的多个存档槽，使用共同父目录整体备份。不会提升到 AppData、LocalLow、Documents 等共享目录，也不会因为旁边有另一款游戏而扩大范围。

Rubinite 的正确目录为 `AppData/LocalLow/Cup Dog Games/Rubinite/Release`。备份包含所有槽位、游戏自己的备份目录、空目录和 `SettingData.json`；云端路径为“Playnite 游戏名 / Release / 时间戳.zip”。用户当前 Rubinite 配置已经是 Release，核对后保留此选择。

原自动选择逻辑会在父子候选中舍弃父目录，可能只保存一个存档槽；此版本改为保留经过验证的父目录。匹配到单槽路径时，会先归并到完整游戏存档目录。批量冲突检查也使用归并后的路径。

旧版单槽备份仍可恢复，恢复目标保持为原槽位，不会替换整个父目录或影响其他槽位。完整父目录备份则整体恢复。旧备份缺失的其他槽位无法从旧 ZIP 中补出，后续完整备份会保存当前所有槽位。

新增 10 个多槽回归测试覆盖目录归并、所有文件打包、空槽位、云端路径、父子候选、单槽模型建议、共享根目录防护、完整恢复、旧单槽恢复及旧配置升级。原备份/恢复、工作流与云端目录回归通过。测试使用隔离目录，不恢复真实游戏存档。

双击上级“启动新版.bat”运行 V1.5。Git 保留各版本及旧 EXE。
