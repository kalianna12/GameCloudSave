# 音效试听页重播修复

2026-10-22 用户反馈同一音效反复听会不一样。旧页使用一个 HTMLAudioElement，每次点击先 pause、再改 src、立即 play，没有等待加载或隔离旧 promise。实际 Chromium 连续点击两个文件，复现旧请求报 `The play() request was interrupted by a call to pause()` 并覆盖当前状态；反复加载也会重新走短音频的媒体加载路径。这能确认播放控制有问题，不能据此断定所有设备上的主观差异都来自同一原因。

试听工具改用一个 Web Audio 上下文和解码缓存，每个 WAV 的字节内嵌到生成页面，支持直接双击 file:// 离线打开。没有 fetch 权限问题，没有随机音效、滤波、均衡、压缩或变速；原文件和处理版分别缓存。每次点击或重播使用同一个不可变 AudioBuffer，从偏移0以原速播放。异步加载成功/失败、结束事件都核对当前请求编号，只有最后一次选择可以起播或更改状态；停止会作废尚未完成的解码。

每次预留50ms起播，前一个被打断的声音仅做4ms收尾、早于下一个声音，不叠加；自然播放不加淡入淡出。零值常量源保持同一个输出上下文，避免每次短音重新建立输出。新增重播、停止、进度、音量和明确的文件/版本状态。只更新试听页面和生成脚本，未改动程序实际运行音频库。

生成：

```powershell
.venv\Scripts\python.exe scripts/create_sound_audition.py --offline
```

已有原文件时可直接离线重建。首次下载不带该参数，仍固定来源提交并检查 Git blob 哈希；本次 GitHub API 限流，所以复用之前核验过的211个原文件。生成目录仍为忽略的 `build/sound-audition`，新增脚本 `scripts/sound_audition_player.js` 是版本控制中的播放器来源。

验证：

```powershell
node --check scripts/sound_audition_player.js
.venv\Scripts\python.exe tests/test_sound_audition_ui.py
```

实际 Qt Chromium，内存浏览器配置、输出静音、本地文件。217个内嵌WAV（211原文件与6个当前效果）逐字节等于磁盘文件并全部成功解码。四次自然结束后的重播仅解码一次，所有起播偏移0、原速且共用同一缓冲；两次浏览器 OfflineAudioContext 渲染逐声道/逐样本完全一致。30次连续原文件/当前效果切换只有最后一次起播；旧失败不能覆盖新状态；解码中停止不会随后起播；重播和音量控件正常。设备输出静音，因此这些测试验证数据和调度一致性，不代替用户设备的主观试听。

刷新本地试听页即可使用。真实游戏库、配置、存档和运行素材未改动，未打包或上传发行版。
