## 打开与布局

运行 workspace 下的 `启动源码版.bat`，在主页左侧进入“手柄映射”。该启动脚本继续使用 `test-data/source-preview`，与真实游戏库分开。

- 上方：完整键盘，包括功能区、导航区、方向键与数字区；下方附鼠标按键和滚轮。
- 左下：Xbox、PS、Joy-Con 三种可切换矢量模型，按物理位置点击或接收拖放，按下与摇杆位置实时反馈。Xbox 使用用户最后更正的参考：非对称摇杆、左下十字键及 ABXY 彩色描边；PS 为对称摇杆与触摸板外观，Joy-Con 为青红双持外观。
- 右下：两个摇杆位置、映射输出、当前绑定编辑、组合录入及按下/松开记录。反向模式显示虚拟输出，未启用时也可预览。
- 最下面：完整按键选择、反向绑定列表、摇杆轻推/重推、鼠标速度、死区与平滑等设置。页面可滚动，拖动到上下边缘会自动滚动。

模型是标准 XInput 控件的三种外观，切换不会改变已保存绑定的物理位置。PS/Joy-Con 实体设备必须先由系统或 Steam Input 转换成 XInput；本轮没有加入原生 HID、触摸板、陀螺仪、SL/SR 或单只 Joy-Con 的独立采集，不把外观选择当成设备驱动支持。Xbox 系统键、Share 和厂商背键也不在标准采集范围内。

截图在 `test-data/input-mapping/`：`forward-dark.png`、`ps-dark.png`、`joycon-dark.png`、`reverse-dark.png`、`light-small.png` 与 `drivers.png`。它们使用隔离数据和模拟中性输入，未向真实游戏注入按键。

## 两个方向

手柄到键鼠现有八组游戏类型模板，可从“游戏模板”预览、单独创建或一键添加全部；绑定、按类型恢复默认和引擎差异见 [游戏类型映射模板](游戏类型映射模板.md)。

| 方向 | 操作 | 输出 |
| --- | --- | --- |
| 手柄 → 键鼠 | 点手柄按键，再点键盘/鼠标；或把键帽拖到手柄按键上 | 单键、最多 12 键的同时组合、鼠标按钮和滚轮 |
| 键鼠 → 手柄 | 点键鼠输入，再点手柄；或把手柄按键拖到键帽上 | 多个虚拟 Xbox 按钮/扳机/摇杆方向的同时组合 |

默认拖放替换绑定，勾选“追加组合”后追加。右侧“录入组合键”会读取实际键盘，全部松开后提交；支持左右 Ctrl/Shift/Alt，录入 F11 不会切换游戏库全屏。反向录入修改当前绑定的输入条件，例如 Ctrl + K → A + LB；下面的列表可选中或删除已有绑定。

键盘以 Windows 虚拟键码保存，附有完整键选择列表；未显示在大键盘上的 F13–F24、媒体键或 OEM 键也可录入/选择。主 Enter 与数字 Enter 当前共用 Enter 的虚拟键码；不宣称能区分所有硬件扫描码、模拟系统安全组合或绕过游戏的输入限制。

“配置管理”支持新建、复制和删除方案，顶部可重命名、切换、保存，最多 40 份。每份方案同时保存两个方向、手柄外观和参数，一次只启用所选方向；不是宏录制或定时连招系统。文件为当前数据目录下 `machines/<本机标识>/input-mapping.json`，不修改游戏库或存档配置；旧方案没有外观字段时按 Xbox 读取。

保存后可直接在游戏库顶部的映射下拉框选择，无需打开编辑器。“无”立即停止映射；`🎮 → ⌨` 表示手柄到键鼠，`⌨ → 🎮` 表示键鼠到手柄。只列出已保存的方案，未保存的新建草稿不进入主页选择列表。选择方案不会弹出编辑器，切回程序内会暂停输出；这个方案是全局映射，只排除本程序，不按游戏进程自动切换。

### 摇杆与鼠标

默认正向：左摇杆八向 WASD，重推附加左 Shift；右摇杆移动鼠标，LT/RT 对应鼠标右/左键。A/B/X/Y 默认对应 Space/Esc/E/R。

“详细设置”中选择左或右摇杆，可设八向按键、鼠标移动、鼠标滚轮或停用。轻推和重推并排显示，用 3×3 方向布局表示实际推杆方向，每格下方显示对应按键。两组可分别选择 WASD、方向键或自定义组合，右上方“两组用 WASD / 两组用方向键”同时更改两组方向，不改附加键和另一个摇杆。点击方向或附加键后，在下方直接录入、清空；也可把键帽拖到方向格。例如重推附加 Shift、轻推留空，反过来也可以。超长组合悬停可见完整内容。

鼠标滚轮模式：摇杆向上/向下滚动，轻推、重推分别设每秒 1～30 格，默认 3 / 12，可反向。首次推动立即滚动一格，随后按时间重复，回中、停止或断开清理余量；本模式不会带入八向按键模式的 Shift 等附加键。

反向模式右下方“滚轮控制摇杆”可分别把滚轮上、滚轮下绑定到左/右摇杆的上下左右方向。保持时间默认 100ms，可调 20～500ms；力度沿用左侧设置，停止后回中，快速反向先取消旧方向脉冲。“编辑”返回同页手柄/键盘和预览区，可设置虚拟按键组合；带 Ctrl 等修饰键的滚轮组合保持独立。在编辑器内滚动也能预览，不需要先开启实际输出。启用中新增滚轮绑定再保存会即时登记原始鼠标输入，不必重新开关映射。新建反向方案同时提供 WASD 和方向键控制左摇杆；已有方案保持原绑定。

死区、方向边界和轻重阈值带滞回，减少临界抖动。鼠标速度按时间计算，保留不足一像素的位移；灵敏度、曲线和平滑可调，回中或断开即清理残留。反向可设常规/轻推力度、轻推修饰键、过渡时间，以及鼠标映射哪个摇杆。对角线按圆形力度归一；反向滚轮事件保留短脉冲，避免游戏采样漏掉一次滚动。

2026-10-20 简化界面续修：映射方向只用完整文字，去掉重复图标，1040×700 下不截断。轻重推无需切换下拉框，底部设置改为全宽；小窗口两组八向、预设、附加键及录入按钮可同时看见。保留页面滚动条与统一主题色，不新增常驻说明段落。旧方案读取时仅补齐新增参数，不替换已有按键。

本次验证：36 项映射单元 + 6 项组件单元；实际鼠标点击、组合录入、独立/同时预设、1040×700 浅色截图、同页滚轮反向与回中、保存及主页方案选择；全屏生命周期及四布局导航回归通过。原生测试向自有隔离窗口发送滚轮，并通过 ViGEm/XInput 回读滚轮方向产生的虚拟摇杆和中性状态，没有向真实游戏注入。性能测试仍保留稳定按键对象和独立采集；本机模型切换约 3～8ms、预览样本年龄 P95 约 3.6ms，结果不代表所有设备帧率。截图新增 `stick-settings-light-small.png`、`wheel-settings-light-small.png`，均位于 `test-data/input-mapping`。

### 启用与停止

启用时先验证并自动保存配置。切换到游戏窗口，松开绑定键、回中摇杆后开始；焦点换到其他窗口也先复位、等待中性输入，避免把原来的长按带过去。本程序获得焦点时暂停输出，实体手柄断开、禁用、换方案或退出会释放已输出按键并复位/移除虚拟设备。程序不会释放原先由实体键盘独立按住的键。

关闭映射窗口后，已启用的映射继续在后台工作；关闭到托盘也保留它。退出程序则停止，每次重新启动默认关闭。`Ctrl + Alt + F12` 为固定停止组合，左右 Ctrl/Alt 均可。编辑中默认按手柄用于选中对应绑定，勾选“手柄导航界面”后改为界面导航，避免按 B 时意外关页。

保留原始键鼠与实体手柄输入，不隐藏设备或拦截游戏中的原始键盘事件。部分游戏会同时看到两类输入；管理员运行的游戏需与映射程序权限匹配，受反作弊限制的游戏可能拒绝模拟输入。

## 驱动与组件

顶部“驱动与组件”提供后台检测、安装缺失组件和重试。正向使用 Windows XInput/SendInput，无需额外驱动；反向使用 vgamepad 和 ViGEmBus。Windows 上 vgamepad 的驱动依赖与安装行为见 [vgamepad 官方说明](https://github.com/yannbouteiller/vgamepad)。

点击安装只补缺失项：源码环境通过当前 Python 安装固定的 `vgamepad==0.1.0`，设置 `VGAMEPAD_SKIP_VIGEMBUS_INSTALL=true`，避免 pip 隐式打开另一个驱动安装器；若缺 ViGEmBus，再下载 [官方 1.22.0 安装程序](https://github.com/nefarius/ViGEmBus/releases/tag/v1.22.0)，核对固定 SHA-256 与 Nefarius Authenticode 签名后，通过 Windows 管理员授权打开可见安装窗口。校验失败、下载失败或用户取消时显示具体结果，不启用映射。附 `/norestart`，不自动重启；安装返回需重启时明确提示。

固定哈希来源为 [Microsoft winget 官方清单](https://github.com/microsoft/winget-pkgs/blob/master/manifests/v/ViGEm/ViGEmBus/1.22.0/ViGEm.ViGEmBus.installer.yaml)。ViGEmBus 已停止维护，入口保留官方发布页；不会从第三方下载站获取驱动，也不会安装实体 PS/Joy-Con 驱动。检测、下载、pip 和签名校验在单独后台任务中运行，映射线程和界面不等待网络。

当前电脑原先已有 ViGEmBus；本轮只在源码虚拟环境补装 vgamepad，未安装、卸载或更新系统驱动。另已实际下载官方文件并通过哈希、签名校验，没有运行这个已安装驱动的安装程序。若是缺少模块的旧冻结发行包，检测会要求使用完整版本，不拿发行 EXE 当 Python 执行 pip。

## 全屏修复

复现了最小化后直接 `showFullScreen` 并立即激活，Windows 随后又恢复成 Windowed、而全屏偏好仍为真的状态冲突。现改为：明确的托盘/单实例恢复先恢复普通或最大化窗口，激活后再做一次有界的全屏切换；重复恢复请求节流，同一状态不重复显示。关闭子页只恢复焦点，不把隐藏/最小化的主库从桌面拉回来，也不在失焦回调中强制循环全屏。F11 禁用按住自动重复，并合并相邻状态变更。

保留窗口化/最大化的退出位置与全屏偏好。映射录入能消费 F11；虚拟手柄自己的 XInput 槽位从游戏库导航采集中排除，防止反向映射驱动主页误导航或启动游戏。

## 开销与验证

续修定位到四个问题：编辑状态原本每 50 毫秒轮询、75 毫秒才发布最后一帧，30 毫秒短按会漏掉；每次发布都会重设整个记录列表、自动选中还通知整份配置，造成多余界面更新；Canvas 阴影绘制在本机约需 1～2 秒；关闭后焦点仍留在侧栏映射入口，向右导航又等同于打开。

现改为编辑期间独立线程约 4 毫秒采样，以本线程的高分辨率等待计时，不修改全局系统时钟周期。当前源码 Python 的 `monotonic` 使用精度约 15.625 毫秒的 GetTickCount64，已将输入积分、鼠标平滑和预览节奏改用高精度 QueryPerformanceCounter，避免几轮 4/8 毫秒采样算出零时长、随后突然跳动。保存每次按下/松开边沿，前台界面用 8 毫秒发布节奏合并最新摇杆位置，由窗口渲染合并成显示帧，逐条插入有界记录，不再每帧重设列表或刷新整份配置；失焦降到 33 毫秒，最小化/关闭停止预览。按钮短脉冲至少给一次可视化反馈，计数保留全部已捕获按下，时间显示到毫秒。原始事件缓冲最多 512 项、显示最近 48 项，均只在内存，关页清空并回中可视化。完整键盘仅在本程序前台预览，排除泛化修饰键的重复项；其它窗口只读取配置涉及的触发键。

三种模型改成预加载的本地 SVG，切换只改变图片可见性和已有按键的位置，不销毁/重建按键对象，也不重画昂贵的 Canvas 阴影。编辑器在程序前台、没有运行游戏时用每轮最多 2 毫秒的闲时预算预建，打开后保留单个编辑器实例，关闭即停止预览采样；未打开/启用前不启动映射采集线程。后台实际输出仍约 8 毫秒一轮，断开降低重查频率，不扫描游戏目录或全部系统进程。

拖放增加目标高亮、按键旁“绑定到…”和顶部完整绑定方向提示；提示不使用会遮挡拖放命中的弹出层。边缘滚动先等短暂停留，避免从底部向上拖动时误滚动。关闭映射页恢复游戏内容焦点，侧栏右键只进入内容，明确按 A 才打开工具。主页方案选择也不会打开工具。窄窗口工具栏自动换行，并调整影院极短视口的文字间距，保留操作按钮，避免新增下拉框挤压原有影院布局。

高精度计时的一次本机隔离运行记录：模型切换后首帧约 3～13 毫秒，预建后的首次窗口显示约 170 毫秒，再次打开约 59 毫秒；采集约 220Hz，预览发布约 95 次/秒，窗口约 52 帧/秒，发布快照年龄第 95 百分位约 3.7 毫秒。其它运行中窗口达到约 62 帧/秒。指标受本机负载、显示刷新率与测试场景影响，不代表实际游戏帧率或所有电脑的延迟承诺，完整记录在 `test-data/input-mapping/performance.json`。
