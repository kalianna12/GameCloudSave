# 源码迭代：二次资料查询与手柄导航

2026-10-10，仅修改 workspace 源码。上一轮三个游戏设置页面、侧栏资料补全、导入选择与预览应用流程已保存为 `e32dfd6`。

## 二次查询

首轮继续按已有资料、平台 ID 和当前名称查询。首轮成功补齐本次所选缺失项的游戏不会进入二次查询；仅对仍缺日期、封面或未识别标签来源的条目追加处理。预览后仍由用户选择应用，已有资料与人工编辑保护保持生效。

- 重试线索包括 Playnite 当前原始名称、导入时保存的来源名称、Steam 返回的商店名称、已有识别记录的英文名/别名、安装目录名和非通用的启动文件名。仅作为查询线索，不改显示名称、安装路径或平台归属。
- 统一全角、标点、空格、中英文大小写、Windows 简繁字形以及独立罗马序号；清理带括号的汉化/免安装等附加说明和版本尾缀。保留作品副标题、续作编号和重制版信息。
- 每来源最多尝试四个完整名称以及一个较宽的标题片段。标题片段只用于发现候选，候选必须与完整名称或已知别名重新评分，不拿片段的搜索排名直接确认。
- VNDB 查询读取原文、罗马字、多语言标题和别名；即使没有图片，也保留可用日期。字段依据 [VNDB Kana API](https://api.vndb.org/kana#post-vn)。
- 首轮要求强匹配；二次匹配允许标题轻微改写，相似度至少 0.87，第一、第二候选差至少 0.08。短名称要求近乎精确匹配，数字和重制版信息不一致的候选拒绝。没有足够依据时保留缺失，并在“显示全部查询结果”中说明原因。
- 两个游戏工作线程，首轮和二次查询均通过 Qt 信号返回预览；停止后不启动后续请求，当前请求结束后收尾。搜索和资料缓存版本更新，旧的漏查缓存不会阻止新逻辑。

Steam 没有完整日期或标为尚未发行时，不再提前结束视觉小说查询；继续查询 VNDB。即使游戏尚未归为视觉小说，二次查询也尝试 VNDB。Steam 已读到的标签不会因为 VNDB 暂不可用而丢弃。

VNDB 日期注明“VNDB（首次发行）”，与 Steam 版本发行日期区别展示，不覆盖已有日期。仅采用资料库完整日期，不让 AI 猜测。已用公开只读请求验证“美少女万华镜雪女”可匹配 `v44184`，返回日期 `2024-04-26`；宽查询后完整名称得分约 0.889。真实游戏库没有写入这些测试结果。

## 手柄导航

- 内页网格导航使用实际 `cellWidth` 与可用宽度计算列数。旧实现把自动列数限制在最小卡片宽度计算的列数，可能与 Qt 实际绘制的行不同；现在上/下按实际列数移动，只有首行向上进入筛选行。
- 鼠标点到某张卡片的操作按钮后，手柄先接管该卡片索引，清除旧子控件焦点，再向同列上一行移动，避免从旧索引跳到顶部或侧栏。
- 侧栏游戏库主页、全部游戏、最近游玩、收藏、系列五项上下选中即显示页面，焦点仍留在侧栏。向右或 A 进入当前页第一款游戏；首页进入第一行第一项。侧栏不再恢复旧游戏索引或旧行位置。
- 未适配手柄的编辑窗口仍拦截方向和确认命令，B 返回；这次没有扩展到原生文件选择器。
