# 本地成就与游戏内弹窗

2026-10-23，仅当前 workspace 源码版；便携版、安装包及现有 V2.5.0 发行包未更新。

同日后续已扩展独立成就管理、批量、多源、Steam BIN 与封面徽标；最新使用方式及范围以 [成就管理、批量匹配与本机数据源](成就管理批量与多源.md) 为准。以下保留首次实现记录，其中“仅本地游戏／不支持 Steam BIN／30 秒图标预算”已由续版替代；续版适配上游算法并保留 MIT 许可。

## 使用方式

1. 打开本地游戏的“游戏设置 → 成就”。手柄 Menu 打开游戏选项后进入设置，LB / RB 切页，方向键和 A 操作，Menu 保存，B 返回。
2. 优先复用游戏资料中的 Steam App ID，以及游戏目录内的成就定义和记录。已有对应资料时自动匹配公开中文成就；也可展开“匹配与记录设置”，搜索游戏并确认具体版本、填写 App ID，或导入 JSON 定义。
3. 核对“成就记录”文件。自动检测发现多个文件／账号时不合并，也不擅自选择；从候选中选本次账号的 JSON / INI，保存方案。成就记录与普通游戏存档不是同一概念。
4. 通过本程序启动游戏。启动前导入已有进度作为基线，确认实际游戏窗口后，每秒在后台检查一次记录。首次导入不刷屏，新的解锁依次弹出，并记入本机历史。
5. 可分别关闭本游戏监听和游戏内弹窗；“预览弹窗”用于检查显示效果，不增加任何成就。

已匹配时收起设置区，让列表获得更多空间。列表显示总数、已解锁数、说明、记录提供的进度和本地时间；未解锁的隐藏成就不显示剧透内容。支持鼠标和手柄滚动查看。

## 支持范围

- 支持已有本地成就文件的游戏，不要求它归属于 Steam 平台条目，也不需要登录或 Steam API Key。
- JSON：以 API 内部编号为键，字段包括 `earned` / `achieved` / `unlocked`、解锁时间及 progress；也支持带内部编号的记录列表。
- INI：每个成就一节的 `Achieved` / `earned` / `unlocked` / `HaveAchieved` 等状态，以及 `[Achievements]` 下 0/1 布尔记录，支持 UTF-8 / UTF-16 和十六进制时间。
- 常见文件名：`achievements.json`、`achievements.ini`、`user_stats.ini`。定义列表中的 displayName 不当作解锁记录，普通数字统计不会被当作解锁。
- 有界扫描游戏、EXE、存档目录，以及对应 App ID 的 GSE/Goldberg、CODEX/RUNE、OnlineFix、SKIDROW、EMPRESS 等常见目录；不扫描整个硬盘，不跟随目录链接。其他位置可手动选择文件。
- 定义兼容 `[{"name":"ACH_FIRST","displayName":"初次冒险","description":"……"}]` 和 Steam schema 包装格式；API 内部编号必须与进度文件完全对应。进度文件本身不能充当完整定义。
- 没有输出可读成就记录的游戏，**仅匹配列表不能自动检测解锁**。本功能不会为游戏注入代码、替换 DLL、修改存档或伪造成就；尚不支持 Steam 二进制 appcache、加密／压缩进度和自定义游戏内存规则。未实现平台账号同步、跨设备成就同步或手工修改游戏成就。
- 本轮通过本程序启动的游戏会建立监听；未通过本程序启动的游戏不会自动建立全库成就监听。

## 普通游玩与 Anime4K

弹窗是独立的轻量原生窗口，不依赖游戏库主窗口是否可见。它位于游戏所在显示器右下方，保持置顶但不激活、不拦截鼠标，不改变游戏焦点。普通窗口／无边框和 Magpie Anime4K 放大共享同一条通知队列，暂时切到其他程序时隐藏，返回游戏后继续显示；游戏退出或通知超过两分钟则丢弃过时弹窗，进度仍保存。

使用 `WindowDoesNotAcceptFocus`、`WindowTransparentForInput`、`WA_ShowWithoutActivating` 和不激活的 SetWindowPos。设置 `WDA_EXCLUDEFROMCAPTURE` 防止弹窗被桌面捕获重复录入。正常运行无需注入游戏或修改 Magpie 的渲染配置。

**独占全屏兼容性有限**，特别是旧 DirectX 游戏；如无法显示，请改无边框／窗口或通过 Anime4K 放大。不宣称支持所有独占全屏、HDR、多显卡、权限等级不同的游戏，也没有用实际游戏存档解锁进行验证。显示器定位按原生监视器设备名选择；本机实际 GPU 验证为当前单显示器，混合 DPI 多屏待实机体验。

## 数据、性能与边界处理

- 本机配置、定义与历史在当前数据目录的 `machines/<本机>/achievements/{config,progress}.json`，图标在其 `icons/` 下；不修改 library.json 或原游戏文件。
- 历史按游戏 ID、匹配 App ID 和记录文件完整路径分开，不混合不同游戏／账号。缓存使用原子替换；缺失、半写入及重置成就文件不清除已记住的解锁，不会在重置后反复弹相同成就。
- 游戏确认退出时补读一次，保留退出前落盘的成就；已无游戏窗口的通知不在桌面补弹。
- 文件读取、发现、保存使用独立串行工作线程；网络匹配与图标下载各自独立，不持有监控线程，已有成就可离线查看。图标按请求分批、有时间预算地缓存，尚未缓存或下载失败时使用奖杯标记，不阻断通知。
- 网络失败不覆盖旧定义；过期异步返回不覆盖后来选择的游戏页。新游戏在首次解锁后才创建记录时也能检测到首次解锁。

## 验证记录

- `tests/test_achievements.py`：10 项解析／定义与状态区分／多账号／历史命名空间／首次文件／断写保护等用例通过。
- `tests/test_achievements_async.py`：旧元数据返回隔离、离线保留、设置验证事务性、首次生成文件、搜索联网期间继续监听、半写重试通过。
- `tests/test_achievements_ui.py --gpu`：真实 QML 80 项列表、900×650 和 1440×900 页面、手柄滚动和保存；临时外部动画窗口写入成就，普通模式弹窗、焦点未抢夺、Alt-Tab 隐藏、捕获排除标志、重置去重通过；官方 Magpie v0.13.0 的实际 Anime4K GPU 输出上弹窗位于渲染表面上方，截图像素和窗口顺序双重断言通过。测试只临时关闭捕获排除以保存可见弹窗截图，随即恢复。
- Steam 公开接口实查 App ID 1057090 返回 **37 项**成就，37 项均有中文名称及内部编号。这只验证定义获取，不表示已读取实际《奥日 2》的成就记录。
- 原启动等待与交接、画质配置、手柄工作流、筛选和随机游戏回归通过。真实 data 的 287 个文件与既有 SHA-256 基线一致。
- 隔离截图与报告：`build/achievement-review/`；GPU 内核仅导入临时测试目录，测试后清理，未在 source-preview 安装或写入任何内容。
