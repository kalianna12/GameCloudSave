# 监听与封面交互优化

2026-10-16 后续：[游戏库视觉与动效改版](游戏库视觉与动效改版.md) 已调整卡片布局、倾斜幅度和跟随方式，以下封面 6 度弹簧效果为上一轮记录，当前以新文档为准。监听与本机保留规则继续沿用。

2026-10-15 源码迭代。只修改 `workspace` 并使用隔离数据测试；没有重建、同步便携版或安装包，没有发布 GitHub 发行包。真实游戏库、配置、凭据和存档未修改。

## 使用方式与交互评估

沿用现有侧栏、强调色和单游戏三个设置页，避免新增重复入口。点击封面或齿轮均进入单游戏设置；存档页直接显示监听 EXE 与选择进程按钮。主界面底部显示监听状态，点击状态进入系统设置的备份页；失败时出现重试按钮。存档历史明确区分自动和手动备份。

开启“自动监听”，为游戏设置存档目录。程序会从已记录的 EXE、安装目录识别进程；不能识别时在单游戏存档页指定实际运行的 EXE。仅导入平台启动链接、安装目录里没有发现实际 EXE 的游戏会提示需要设置，不显示虚假的监听成功。游戏运行期间保持程序或托盘开启。

在“设置 → 备份”调整“每款游戏本机自动备份保留份数”，默认 5，范围 1～100。用户已明确选择：**仅清理本机自动备份，云端保留**。手动备份不限制；修改上限后在该游戏下一次自动备份时执行清理，旧版产生的启动/退出自动备份一并计数。清理不会调用云端删除；超过上限的旧本机自动备份即使上传失败也可能被清理，应及时重试上传。

封面响应鼠标位置产生最大约 6 度的弹性倾斜，手柄选中时轻微倾斜，并播放一次暖白扫光。选择静止后不循环播放。滚动、窗口失焦、关闭“界面动效”时停用。收藏星标保持独立点击，主题强调色焦点框保持可见。

这些调整减少了“进高级设置找监听进程”和“通过齿轮才能进入设置”的步骤。真实手柄手感、不同 DPI 与游戏帧数仍需实际体验，不能由模拟输入和短时渲染测试替代。

## 监听与存档实现

- 独立线程进行进程采样，不再因主任务忙碌跳过退出事件；主任务忙碌时，已确认的退出进入持久化队列，空闲后处理。
- 默认每 5 秒采样，可设置 2～60 秒。先读 PID/名称，只对候选游戏读取 EXE 路径；缓存进程路径及按游戏配置生成的 EXE 候选，不在每次轮询递归扫描游戏目录。已有监听间隔设置保留。
- 游戏运行中不执行自动压缩或上传。连续两次缺失且间隔至少 3 秒才确认退出，减少启动器切换或短暂进程状态变化造成的误判。检测到其他受监控游戏运行时，自动任务等待。
- 每次被检测到的游玩结束产生一个会话任务；启动时不生成备份。队列与快照会话键防止重复创建快照，重试上传复用原文件。应用重启后可继续处理已经排队的任务；退出应用后不能继续检测新结束事件。
- 本地保存成功后才上传。失败显示实际阶段、保留可用的本机备份，用户可重试；不会每次轮询重复弹通知。网络内部重试仍遵循已有传输设置。
- 后台工作只降低自身工作线程的 CPU/I/O 优先级，不修改游戏进程。压缩直接写入临时 ZIP 后原子替换，去除先复制完整存档树的重复磁盘操作；自动备份使用较低压缩级别。文件大小或修改时间在读取期间变化时拒绝完成该快照，保留明确失败状态。
- SQLite 初始化显式关闭连接，修复数据库文件句柄延迟释放。保留自动快照只删除对应游戏快照根目录内的已记录文件，删除失败时保留记录。

轮询存在检测窗口：少于一次采样间隔的极短运行可能无法识别，应用未运行时也不能补推断游戏结束。游戏重新启动时，已经开始的文件或网络操作不能瞬间撤回；线程后台优先级用于减少竞争，不构成零帧数影响保证。

## 安装与卸载

本机只读检查结果：HKCU、HKLM、HKLM WOW6432 卸载注册表中未发现 GameCloudSave；默认当前用户安装目录，以及用户/公共桌面和开始菜单中未发现对应安装或快捷方式，未发现正在运行的 GameCloudSave 进程。因此结论为“未发现已注册安装版”，不推断任意其他磁盘目录都不存在副本。现有工程便携程序保留，没有执行安装或卸载。

本轮完善的是安装/卸载源码：

- 安装器优先选择已注册安装目录升级，避免同用户重复注册到另一个目录；完成后可明确点击启动。
- 升级移除旧清单中已经废弃的程序文件，保留未跟踪的用户文件。安装失败回滚程序、旧清单、快捷方式及原注册表值。
- 卸载在删除前完整校验清单和路径，拒绝个人数据、凭据路径及越界路径。便携目录缺少安装记录时提供明确提示，避免将其当作安装版卸载。
- 保留当前用户安装、托盘进程检测、卸载程序退出后自删除及个人数据保留行为。注册静默卸载命令和禁止系统维护入口。

V2.4.0 现有安装包和便携版不包含本轮修复，需以后明确授权发布时重新构建。

## 验证

全部使用 `workspace/test-data` 下的隔离测试，不启动真实游戏、不还原真实存档。

- `test_watch_engine.py`：12 项通过，覆盖退出一次、忙碌排队、上传失败不反复重试、同一快照重传、队列恢复、会话去重、本机 5 份/可调整、清理过期文件对应的重试记录、手动不限、云端不删除、低开销候选采样及平台安装目录发现。
- `test_installer_transactions.py`：8 项通过，覆盖升级清理边界、失败完整回滚、新安装失败恢复、个人数据清单拒绝、凭据拒绝、重复注册拒绝、便携目录和无效清单提示。
- `test_cover_motion.py`：真实加载 QML，验证手柄单一焦点扫光、鼠标倾斜、动效关闭/滚动暂停、收藏不误开设置、封面打开三个设置页。截图为 `test-data/cover-motion/controller-shine.png`、`mouse-tilt.png`，测试报告为同目录 `report.json`。
- 既有监听、基础服务、来源同步、导入、安装升级、多存档槽、云端路径，以及补全、网格/首页导航、输入、向导批量、设置 UI 回归通过。Qt 界面回归逐个运行以避免窗口焦点干扰。
- 当前机器只读采样 30 次：进程轮询耗时中位数 1.743 毫秒、P95 2.256 毫秒；按 5 秒间隔估算单核 CPU 占用约 0.063%。一次选中动效完全结束后，300 毫秒观察期内静止窗口重绘 0 帧。此为短时工程测量，没有做真实游戏 FPS 基准测试；原始数据在 `test-data/cover-motion/watch-performance.json`。

实现参考：[psutil 进程 API](https://psutil.io/)、[Qt Quick Rotation](https://doc.qt.io/qt-6/qml-qtquick-rotation.html)。
