# 重构方案（第一阶段）

推荐 Python + PySide6 + QML/Qt Quick，SQLite 保存游戏与快照索引，UTF-8 JSON 保存非敏感设置、存档匹配规则和 Playnite 导入清单。保留现有核心作为迁移基线，不直接改写已验证的快照与恢复行为。

## 游戏库

Xbox 风格深色背景、绿色强调色、大封面卡片、现代 SVG 图标。每张卡片依次为封面、中文名称、启动/设置/云存档/删除四个图标按钮，带提示和键盘焦点。删除默认仅移除管理条目，不删除游戏文件或快照。

支持窗口自适应、封面尺寸、每行数量、间隔和缩放；自动列数与指定列数为两种布局模式，小窗口限制最小卡片宽度。设置持久化。封面按显示尺寸解码、异步加载和缓存，网格只创建可见项目。

## Playnite

本机检测到 Local 和 Roaming 下的 Playnite 目录，尚未确认有效游戏库。优先通过 Playnite 官方扩展 API 导出 JSON 与封面，导入名称、稳定 ID、安装目录和启动动作；用 Playnite ID 去重，重新导入保留存档配置。启动优先交给 Playnite，避免简化复杂启动动作。避免直接修改 Playnite 数据库。

接入失败后再做手动选择 EXE/安装目录和自定义封面；其他游戏来源放在后续阶段。

## 全局云设置

设置页面一次输入 WebDAV 地址、账号和密码，测试连接、浏览 AList 目录、选择根目录并确认。采用 WebDAV PROPFIND 浏览和 PUT 上传；旧 rclone remote 提供兼容迁移。凭据使用 Windows 凭据存储，JSON 不存明文密码。

所有游戏继承全局位置，按稳定游戏 ID 自动创建独立目录，显示名保留中文。保存顺序：本地快照完成并写入索引 → 上传队列 → 后台上传 → 更新状态。网络失败保持待上传记录并支持重试；本地备份、进程监听和 UI 不等待网络。防止同一游戏并发压缩与恢复。

## 存档匹配与 AI

规则优先扫描 LocalAppData、Roaming、LocalLow、Documents/My Games、Saved Games、游戏安装目录及有依据的 Steam userdata 路径。支持中文名、英文别名和 Playnite 元数据。JSON 是常见存档格式之一，但不能仅凭扩展名确认存档。

限制扫描深度和目录数量，缓存结果。DeepSeek 用于别名和候选排序，返回 JSON（候选 ID、置信度、理由），严格校验，只接受本地实际存在的候选目录。低置信度交给用户选择；AI 不直接指定任意备份路径，不发送存档内容。设置页提供启用开关、API Key 和可配置模型。

参考 TRANSLATE 项目的 PySide6、后台工作线程、请求超时、JSON 校验和缓存实现，不复制其密钥或翻译业务。

## 验证顺序

1. 隔离验证旧核心：中文游戏名、本地 ZIP、上传失败保留、恢复与历史。
2. QML 游戏库与设置页，用示例游戏展示布局。
3. 接回旧核心，所有测试使用 workspace/test-data。
4. Playnite 导入与启动，再做 WebDAV 连接/目录选择/队列。
5. 存档扫描和 DeepSeek 匹配，性能验证及独立打包。

本阶段只完成源码迁入、上传说明和框架准备；尚未交付新版 UI 或验证真实云上传。
