## 一次设置，批量执行

先在“云端存储”设置统一位置，再打开“AI 匹配”，点击“自动配置并备份云端 · 已安装游戏”。无需预先为每个游戏填路径。

程序分两个阶段：
1. 名称识别与本地扫描，核查候选内的真实存档文件，集中检查多个游戏是否指向同一目录。
2. 对符合证据条件且不冲突的结果自动保存本机路径、创建本地 ZIP，然后上传统一云端位置；逐个保存状态。

模糊候选、空目录、多个评分接近的候选、共享目录留在结果中心集中核对。程序不会仅凭“目录存在”自动上传。已有用户手动指定的有效存档目录继续使用。

支持“自动配置并保存本地”和“批量补传”。上传失败保留本地 ZIP。批量流程可停止；当前请求结束后停止后续处理。真实游戏存档不会被自动恢复或覆盖。

本地规则支持常见目录、游戏安装目录、游戏名前缀的存档文件夹（如 fate_savedata），以及 sav、save、sl2、celeste、ksd、es3 和具有进度证据的 JSON 等文件。Playnite 未提供安装目录时可从已设置的 EXE 推导。

## DAV 引导

引导为“连接 → 选目录 → 验证保存”。现在单击文件夹直接进入，单击文件预览。AList 需进入实际挂载文件夹，再选择保存位置；所有游戏共享该位置。

“验证读写权限并保存”会列目录、写入一个独立测试文件、删除该文件，再保存设置。可以浏览但不能写入的目录不会被误认为上传位置配置完成。AI 窗口中的云端位置可直接打开引导；尚未配置时点击云端自动流程会先打开引导。

## DeepSeek 输出修复

旧请求的 1800 token 限额容易在思考阶段耗尽，产生空白或截断 JSON。本轮显式关闭思考模式，首次使用 4096 token；空白、截断或无效 JSON 最多重试三次，后续请求提高至 8192 token。成功识别结果缓存在本机，每次仍重新验证本地路径。

AI 服务暂不可用时，只要本地扫描仍有结果，结果会显示本地候选和 AI 提示，而不会把整个游戏都标为匹配失败。参考：https://api-docs.deepseek.com/guides/thinking_mode/
